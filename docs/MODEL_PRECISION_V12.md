## 网页几何预算

准备工程为 `assets/blender/orbital-dual-bake-v12.blend`，记录 373,203 个三角形、100 个网格；比 V11 的 320,757 个三角形增加 52,446，约 16.4%。37 个室内根资产、93 个室内 ID 与 2 个外部 ID 保留。最终 GLB 已独立校验，为同样的 373,203 三角形、100 绘制图元及 10 张内嵌图像。

| 对象 | 本轮预算选择 |
| --- | --- |
| 室内静态建筑 `room_static` | 不再执行 Collapse 减面，保留评估后的倒角几何 |
| 左 / 右终端 `terminal_panel_L/R` | 各 10,000 三角形预算 |
| 盆景 baked owner `glass_bonsai_terrarium` | 18,000 三角形预算；玻璃另算 |
| 其它资产 | 保留既有预算，不进行全场细分 |

预算选择参考审计中的实际 CPU 减面试验：终端 10k 时最差部件的单向源顶点最大距离约 0.360 mm；盆景 18k 时最差部件约 0.990 mm。测量是源 evaluated mesh 顶点到同 owner 网页网格的单向 BVH 最近距离，不是双向 Hausdorff 距离，未覆盖面内采样，也可能低估薄层间误差。这些数据支持预算取舍，不是最终 V12 GLB 的完整误差保证；详细逐对象与 P95 结果见原审计。

增加几何需付出顶点处理和传输成本；本轮网页检查与 GPU 采样见下文，不能从数值误差降低推导稳定 120 FPS。

## UV 实验未启用

`refine_architecture_uv_v12.py` 已在真实 V12 prepared 的临时内存副本中试验，但本轮**未启用**。它在建筑权重 1.6 时提高建筑面积加权纹素密度约 13.9%，同时降低可见 / 不确定平台顶面和侧面倒角密度约 28.8%；不接受这个整体取舍。

| V12 试验指标（texel/m） | 原准备布局 | helper 权重 1.6 |
| --- | --- | --- |
| 建筑全部表面积加权 | 98.869 | 112.637 |
| 保留的可见 / 不确定向上平台面 | 101.879 | 72.541 |
| 保留的侧面与倒角 | 88.478 | 62.999 |

试验通过 UV 有限、0–1 范围与条带无翻折 / 无退化检查，只能证明操作有效，不能证明视觉净收益。保持现有 4K 建筑图集及 Smart Project / 打包策略；几何变化对应的 UV 和贴图仍需重新生成与烘焙。未升为 8K，也未宣称亮边纹素不足、碎岛或整套材质已完全修好。

helper 留作明确的可选实验，后续可研究墙顶和窗框连续条带的定向面积分配，避免再用整面墙统一加权牺牲可见平台精度。
