# V11 模型精度只读审计

日期：2026-09-22。仅审计并写入本报告，未改 UI、模型、贴图或现有脚本；未进行 GPU 渲染，也未保存临时 Blender 场景。UV 与减面试验均在短生命周期的后台 Blender 内存中执行。

- `assets/blender/orbital-dual-bake-v11.blend`：`ORBITAL_ATELIER_V2` 源场景及 `WEB_DUAL_V8` 待烘焙网格。

几何误差使用源 **evaluated mesh 全部顶点** 到同 owner 的网页网格 BVH 的单向最近距离，单位按当前 Blender 世界坐标换算为 mm。墙体初筛每物件至多约 1,500 个顶点（步长取整会略超）；终端/盆景预算对照使用全部源顶点。该方法不是双向 Hausdorff 距离，未覆盖面内采样，也可能低估薄层之间的最近距离；表中数值是定位和预算比较依据，不代表完整几何质量保证。

## 最高优先级的三项改进

### 1. 重分配建筑图集，先收回平台底面与层间面占用；不要直接升 8K

当前墙、窗框、平台共用 Atlas 0 的 4096² 纹理。细边轮廓已经有几何，但亮边被烘成约一像素宽，表现会像几何锯齿。

| 网格 | 全部表面积 m² | 实际 UV 面积/整张图集 | UV 岛 | 面积加权纹素密度 |
|---|---:|---:|---:|---:|
| `WEB8_room_static__baked__A0` | 295.904 | 17.703% | 416 | 100.2 texel/m |
| `WEB8_architecture.platform__baked__A0` | 451.920 | 28.653% | 27 | 103.1 texel/m |

纹素密度计算为 `4096 × sqrt(sum(UV 三角面积) / sum(世界三角面积))`，**包含背面、底面和封闭层间面，并非相机可见面积密度**。总有效 UV 面积只有 46.356%。平台占已分配 UV 面积的 61.8%。建筑有 129 个岛面积不足 64 px²，181 个不足 256 px²，75 个为单三角岛；17.9% 建筑三角形在 UV 中不足 1 px²。

平台进一步按三角面世界法线区分；向上水平面以面心向 +Z 射线检查是否被另一平台面覆盖：

| 平台表面组 | 三角形 | 面积 m² | 占整张图集 |
|---|---:|---:|---:|
| 向下水平面 | 90 | 213.246 | 13.710% |
| 被上层遮住的向上水平面 | 47 | 139.901 | 8.995% |
| 向上可见面 | 41 | 73.342 | 4.715% |
| 侧面与倒角 | 2322 | 25.431 | 1.233% |

这说明约 **22.70% 整张图集** 用在底面/层间面上，约占平台 UV 的 79.2%。射线是面心采样，只用于判别水平层叠结构；不是完整相机可见性测试。网页镜头 polar 范围当前 0–π/2，也不会绕到底面下方。

CPU 内存中复制两网格，仅重新 Smart Project：

| 角度 / island_margin | 建筑岛数 | 建筑 texel/m | 平台 texel/m | 总 UV 面积 |
|---|---:|---:|---:|---:|
| 现有 66° / .003 | 416 | 100.2 | 103.1 | 46.36% |
| 75° / .003 | 352 | 101.0 | 101.8 | 45.91% |
| 80° / .003 | 387 | 101.5 | 103.4 | 46.96% |
| 80° / .001 | 387 | 107.5 | 109.5 | 52.68% |

**结论：只改角度或压小 margin 收益不足。** 最小 margin 那组只提高建筑密度 7.3%，却增加邻岛串色风险，不能直接替换当前 16 px 扩边烘焙。

建议保持 4K 和现有材质/交互层级，把底面、封闭层间面的 UV 降权，保留模型实体，不删除遮挡结构；可见地板、墙顶、窗框金属亮边独立分组，按可见贡献重分配面积。倒角采用连续 strip UV，减少单三角碎岛；最终使用明确像素间距与一致烘焙扩边。不能把不同光照面的 UV 简单重叠，否则昼夜投影会串到另一面。

风险：Atlas 0 的昼夜两张贴图必须一起重烘并同时更新；任何 UV 改动都不能复用旧光照纹理。无需增加图集分辨率或额外实时灯光；是否增加 draw call 取决于实现是否拆材质，推荐仍用同一图集。

### 2. 只给两个终端和盆景补足几何预算，保留其它已足够的曲面预算

`_triangle_budget()` 当前把终端 owner 各压到 1,800、盆景 baked owner 压到 7,000。合并后 Collapse Decimate 会让框体和底座与装饰物竞争同一预算。实测这些对象的误差明显高于工作椅和茶几。

| owner / 当前网格 | 源评估 tri → 网页 tri / verts | 最明显部件 | 当前最大 / P95 误差 |
|---|---:|---|---:|
| `terminal_panel_L` | 57,900 → 1,797 / 960 | `P_Terminal_L_AluminiumFrame` | 7.463 / 5.781 mm |
| `terminal_panel_R` | 57,900 → 1,800 / 960 | `P_Terminal_R_AluminiumFrame` | 7.463 / 5.780 mm |
| `glass_bonsai_terrarium` baked | 37,528 → 6,996 / 4,023 | `P_Terrarium_Base` | 20.908 / 17.658 mm |
| `furniture.work_chair` | 48,652 → 8,000 / 4,134 | `F_Chair_Floating_Base` | 2.019 / 1.304 mm |
| `furniture.coffee_table` baked | 12,264 → 4,500 / 2,262 | `F_Coffee_Twisted_Metal_Pedestal_1` | 1.516 / .803 mm |

两终端各 24 个源零件，盆景 227 个 baked 源零件。独立 CPU 试验重复当前 evaluated→join→Collapse Decimate 流程，仅改变预算；不包含盆景玻璃球。

| 预算试验 | 实际 tri / verts | 关键误差：最大 / P95 |
|---|---:|---:|
| 终端 L / 6,000 | 6,000 / 3,060 | Frame .80659 / .67053 mm |
| 终端 R / 6,000 | 6,000 / 3,060 | Frame .80653 / .67043 mm |
| 终端 L / 10,000 | 10,000 / 5,072 | Frame .01133 / .01127 mm；最差 ScreenBezel .36042 / .26041 mm |
| 终端 R / 10,000 | 10,000 / 5,072 | Frame .01125 / .01116 mm；最差 ScreenBezel .36038 / .26045 mm |
| 盆景 / 14,000 | 13,998 / 7,580 | Base 1.6714 / 1.0902 mm；Soil 1.76811 / 1.19469 mm |
| 盆景 / 18,000 | 17,999 / 9,605 | Base .98736 / .73864 mm；Soil .67592 / .62305 mm |

盆景 18k 的 PolishedBaseRim 最大/P95 为 .64224/.50849 mm，最差部件 MossPad_00 为 .98995/.71793 mm。建议 **终端各 10k、盆景 baked 18k**，比当前共增加约 27.4k tri，不恢复终端各 57.9k 的全部高密源网格。继续保持各 owner 和小零件稳定 ID，玻璃单独预算。

工作椅、茶几及莫比乌斯雕塑目前没有同等级的大轮廓损失证据，不建议一起盲目增加网格。橙色休闲椅本来就完整保留 65,854 tri / 33,265 verts（32,728/32,746 面为 smooth），其网页质感更应从图集与烘焙排查。

风险：上述预算的屏幕观感和 GPU 成本仍需真实网页测试，数值误差降低不等于保证 120 FPS。改变网格后对应 Atlas 2 昼夜纹理须重烘；不应将新 UV 与旧 Atlas 2 混用。

### 3. 墙顶先修源曲线/法线，再保护硬表面倒角；不要把大折面全归于导出丢修改器

`room_static` 源评估 36,212 tri → prepared 18,000 tri / 9,171 verts。当前 prepared 有 6,652/18,000 smooth 面，`has_custom_normals=True`。实际源码先 `evaluated_get(depsgraph)`，再 `new_from_object(..., preserve_all_data_layers=True)`；被检查的源 Bevel / WeightedNormal / Solidify / Subsurf 均开启 viewport 和 render。没有“修改器完全没应用”的证据。

源顶点到 prepared 的墙体误差初筛：

| 源物件 | 源评估 tri | 最大 / P95 |
|---|---:|---:|
| `V10__A_SweepingTopBand` | 3,972 | 1.079 / .380 mm |
| `V10__A_BackWall_Graphite` | 868 | .976 / .185 mm |
| `V11__A_DisplayTowerBack` | 1,192 | .887 / .482 mm |
| `V11__A_DisplayTowerFrame` | 1,904 | .733 / .328 mm |

因此 50% 减面确实影响毫米级倒角，但它本身不足以解释渲染中墙顶大块折面。源 profile 连续性、转角连接、局部面法线应由墙顶修复任务先解决；修复后的室内建筑和窗框建议不再与全部静态杂项一起接受 18k 的 Collapse 上限，保留源倒角评估几何，并与第 1 项更合理的 strip UV 同步。

风险：直接切换 `shade_smooth` 到全部墙面会使原本平直的硬表面变软，不能把 smooth 面占比当作质量目标。修改源墙形状后，旧阴影/高光图无法复用，必须重烘 Atlas 0。本文不提供或覆盖墙顶修复脚本。

## 法线、玻璃和材质的排除项

- 最终 GLB 的 **100/100 primitive 都有 NORMAL 属性**。共 367,246 个导出法线向量，无非有限值；向量长度偏离 1 的最大值 `1.47e-7`。这不证明法线方向都正确，但明确排除了“导出完全丢法线”与非法/零法线。
- `WEB8_furniture.coffee_table__glass__A1` 没有减面：源/网页均 1,276 tri，640 Blender verts，320/562 smooth 面、custom normals 保留；GLB 因法线/UV拆顶点为 1,448 verts。无边界边、无非流形边。茶几玻璃变平不是“玻璃面数下降”造成。
- `WEB8_glass_bonsai_terrarium__glass__A2` 9,984→2,500 tri，1,254 verts。两个闭合壳体分别 629/625 verts；0 边界边、0 非流形边。内外壳 BVH 无相交候选，未发现壳体互相穿透。不能据黑边视觉直接判为玻璃穿模。
- `WEB8_glass_cutting_planter__glass__A3` 768 tri / 448 verts 完整保留，384/384 smooth 面。128 条边界边来自开口容器结构，需要结合源造型判断，不应自动封口。
- 所有最终材质都转为 `KHR_materials_unlit`。导出器把玻璃换成常量 `[.69,.81,.86,alpha]`，其中茶几 alpha `.34`，其余这些玻璃 `.13`；原折射、Fresnel、动态镜面反射均未保留。网页还使用 FrontSide / single pass。正反面层叠与匀色混合会改变玻璃边缘观感，不能靠增加顶点还原 Blender PBR 的折射反射。
- `_isolated_material()` 主动断开 Principled 的 Normal 输入；导出又移除 `normalTexture`。微表面法线没有参与最后实时着色，这是当前烘焙策略的取舍，不是 GLB 损坏。优化前应把源曲线/几何、静态高光像素密度和玻璃简化材质分别比较。

## 建议验收顺序

先修墙顶源几何并调整 Atlas 0 分配，同时将终端/盆景预算提高至实测档位；只重烘受影响的 Atlas 0 / 2。随后用同相机的日景和夜景近看窗框、墙顶、终端框体、盆景底圈，再测实际网页帧时间。其余小物件保持独立交互，不为“精度”全场细分，也不把图集直接扩为 8K。

## 补充：获授权实现 V12 UV hook 的 CPU proof

新增 `assets/blender/scripts/refine_architecture_uv_v12.py`，接口 `refine(atlas, group, size) -> dict | None`，仅处理 Atlas 0；不调用保存、不渲染、不修改实体网格。父流程可在 `smart_project` 后调用，也可在 V12 prepared 中单独调用后由父流程保存。与此前只读审计的范围不同，这是随后明确授权的新 helper。

安全处理如下：

- 全部朝下的**水平面**与可见 45°倒角在 UV loop 上分开；实体仍封闭。
- 朝上的水平面，对每三角形中心、近三顶点、近三边共 7 点，沿上半球 65 个方向中正面朝向的方向检查遮挡；只在全部样本被平台自身遮住时降权。其它可见/不确定面不降权。
- 6 个大平台倒角环以 XY 实际凸轮廓累计周长作为 u、高度作为 v 展开；各拆 4 段，避免一条约 33m 长的 strip 限制整张图集尺寸。每组展开后恢复原 UV 总面积，保留可见倒角相对面积。所有成功展开组均为 0 翻折、0 退化三角形；异常组自动保留旧 UV。
- 隐藏岛线性缩小到 .2（面积 4%）；重新打包使用 `margin_method='FRACTION'`、`margin=16/4096`、`shape_method='CONCAVE'`、`merge_overlap=False`。16px 是 Blender pack 的设置，不伪称已经逐岛测出最小边界间距。材质图集不增加，不意图允许跨岛重叠。
- 检查 UV 数值有限且在 0–1 内，并在 mesh 记录一次性标记，防止重复缩放。

V11 prepared 的纯内存 proof（没有保存旧 blend）：

| 指标 | 原 V11 | helper，建筑线性权重 1.6 |
|---|---:|---:|
| 建筑 UV 岛 | 416 | 416 |
| 平台 UV 岛 | 27 | 64 |
| 建筑 UV 面积 / 整张图集 | 17.703% | 22.460% |
| 建筑全部面积加权 texel/m | 100.186 | 112.847（+12.6%） |
| 平台全部面积加权 texel/m | 103.137 | 41.376（包含主动缩小的隐藏面，不能代表可见面） |
| 总 UV 面积 | 46.356% | 27.072% |
| 降权隐藏岛 | 0 | 9 |
| 用于验证的遮挡射线 | — | 17,806 |
| CPU helper 时间 | — | 约 3.8 秒 |

9 个隐藏岛原面积合计约 20.15% 整张图集；6 个倒角环 strip 保持展开前的面积比例，所有 1,094 个 strip 三角形均无翻折/退化。平台可见面最终受全图统一 pack scale 影响，约为原密度的 **70.4%**（典型 103→约73 texel/m），这是把像素优先给建筑的明确代价。若不接受这一地板/底沿精度交换，不应启用权重 1.6。

尝试结果也有明确上限：权重 1.15 时建筑仅 100.329 texel/m，权重 2.0 时也只有 115.824 texel/m。因此没有继续加大权重，也没有宣称图集利用率或全场精度整体提高。严格 16px padding 加上建筑 416 个碎岛消耗大量空间，单纯缩平台底面不能解决全部问题；本 helper 的可量化收益是定向建筑密度和有序平台倒角 UV。V12 源墙修复及免 Collapse 后的 UV 岛数可能不同，父流程必须以实际 V12 报告和近看截图决定是否保留这项 hook。

### 实际 V12 prepared 复核及最终建议：本轮不启用 helper

在父流程已生成的 `assets/blender/orbital-dual-bake-v12.blend` 上，再次仅复制到临时内存场景测试；未保存 V12，也未改网页资产。V12 源墙重建和取消建筑 Collapse 后，建筑岛数由 V11 的 416 降为 319，但该 helper 的取舍仍不理想：

| 真实 V12 指标（texel/m） | 原 prepared | helper 权重 1.15 | helper 权重 1.6 |
|---|---:|---:|---:|
| 建筑全部面积加权 | 98.869 | 99.976（+1.1%） | 112.637（+13.9%） |
| 保留的可见/不确定向上平台面 | 101.879 | 89.583（−12.1%） | 72.541（−28.8%） |
| 保留的侧面与倒角 | 88.478 | 77.798（−12.1%） | 62.999（−28.8%） |
| 总 UV 面积 | 44.770% | 24.509% | 26.862% |

向上平台分组是没有被严格多点遮挡验证判为隐藏的所有水平面（113.01055 m²）；侧/倒角分组为其余非水平面（25.43106 m²），均独立比较处理前后，不含主动压缩的隐藏面。6 环 strip 的无翻折/退化检查与全体 UV 0–1 检查均通过，CPU 约 5 秒；但这仅证明操作有效与边界安全，不代表视觉净收益。

**最终建议：先发布到本地预览已完成的 V12 墙体几何、终端 10k ×2、盆景 baked 18k；本轮不要启用这个 UV helper。** 不值得用约 29% 可见平台密度换 14% 全墙密度。脚本保留为明确标记的 opt-in 实验，不自动接入；下一轮若处理 UV，应把资源定向到墙顶/窗框连续条带，避免再次对整面大墙统一加权。不要因此阻塞当前几何修复的烘焙和验收。
