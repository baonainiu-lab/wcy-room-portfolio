# 轨道雕塑入场 V2

2026-09-25。本版以简洁的原创轨道雕塑替换开头的立方体，继续使用现有首次下滑触发、房间逐步展开与物件错峰出现的编排。它取代 [Cube Intro V1](CUBE_INTRO_V1.md) 的六面铰链方块；V1 文档原样保留作历史，不能据其中的方块描述判断当前开场。

## 最新用户指示

用户先提出：

> 开头不要是方块了 重新设计设计个模型 但不要复杂的符合整体内容的模型

随后进一步限定范围：

> 开场动画就用目前这个 就是下滑展开的动画 可以优化的更流畅房间展开的动画衔接更好只不过把一开始的方块展开替换掉 替换成设计的模型

因此本轮保留已存在的欢迎文字、进入手势与房间展开流程，替换开头模型及其衔接动作。只在当前独立项目中做本地预览；没有修改旧项目、推送仓库或部署域名。

## 模型与来源

`welcome-orbit-v1` 由本项目在 Blender 中新建，以现有房间的轨道、深蓝金属、银色圆弧和暖色细节作为造型语言。它由四个独立部件组成：

| 部件 | 造型和用途 | 三角形 |
| --- | --- | ---: |
| `welcome_base` | 深蓝薄椭圆底座，作为模型与房间底部之间的视觉联系 | 896 |
| `welcome_ring_left` | 银色左半环，带少量铜色端面，转场时向左打开 | 2,076 |
| `welcome_ring_right` | 银色右半环，带少量铜色端面，转场时向右打开 | 2,076 |
| `welcome_core` | 暖白陶瓷球，转场时向底座收拢并缩小 | 2,976 |

共 **4 个网格、8,024 个三角形、3 种 PBR 材质**，没有图像贴图。造型和材质常量为本项目制作，没有下载第三方模型、材质图或 HDRI。完整资产来源、单位、坐标转换、独立节点、包围盒与导出统计见 [welcome-orbit-v1.source.json](../public/models/welcome-orbit-v1.source.json)。

Blender 使用 Z 轴向上，GLB 导出为 Y 轴向上、米制。运行时根据模型包围盒最长轴归一化并居中，避免把旧立方体的单位尺寸直接套在新模型上。上表是来源与文件统计，不代表新模型的浏览器视觉验收通过。

## 当前衔接方式

`src/cube-intro.js` 的文件名和 `createCubeIntro` 接口作为历史命名保留，其运行对象现为实际加载的 `welcome-orbit-v1.glb`。状态输出为 `revision: 2`、`model: welcome-orbit-v1`，不再创建六面方块网格。

1. 资源加载和编译完成后，轨道雕塑在米白环境里约 0.7 秒弹性出现，再移动让出欢迎文字；底部箭头淡入等待。
2. 首次向下滚轮、手机向上轻扫、箭头点击或键盘进入触发自动时间线。欢迎字退入遮罩，相机平滑趋向已有房间构图。
3. 雕塑平移、扩大并轻转，两瓣银环向左右分开及转开；陶瓷球向底座下降并收小。模型与开始显现的房间交叠，临时雕塑随后淡出。
4. 现有房间从其真实底部支点展开，墙面陈设、家具、桌面物件、设备和椅子保持原来的组间衔接。36 件资产继续各有动作、大小相关时长和偏移，并保留独立交互层级。
5. 姓名和身份文字与展开交叠出现，仍为“姓名待补充”“身份介绍待补充”。完成后原姿态恢复，临时雕塑释放，现有 UI、镜头与物件交互重新启用。

首次手势只进入一次，重复滚动不会重放或倒放。播放中输入锁、跳过按钮、Escape、减少动态效果、加载失败提示与重试入口继续使用现有实现。手机与桌面的构图由同一控制器按视口计算；实际跨尺寸表现留待本版浏览器检查。

雕塑和真实房间使用同一场景及渲染器。金属反射在准备阶段由已使用的 Three.js `RoomEnvironment` 经 PMREM **一次预计算**，没有下载 HDRI，也没有每帧重建反射探针。现有地面与天空由米白逐渐回到正常环境；接触阴影和烘焙表面暗部继续按房间生成阶段恢复。雕塑几何、材质和反射目标在结束或释放时清理。

本轮未替换真实房间 GLB、长廊资产、个人文案、已选择的寒蝉圆黑 Heavy 字体或现有作品导航。原先 37 个房间根节点中的平台随主体出现，其余 36 件资产仍由 `room-entry.js` 管理；新雕塑四部件只属于开场临时模型。
